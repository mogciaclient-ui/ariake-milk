# 実装計画

## 1. 基本方針

* 一度に全機能を実装しない
* 現在のプロジェクトを調査してから設計を確定する
* `/` のログインページを維持する
* 認証・権限・データ境界を最初に作る
* UIより先にcompanyIdとofficeIdの扱いを決める
* 顧客IDを中心に関連データを接続する
* 配送、注文、営業などの基本業務を先に作る
* AI機能とLINE機能は基本データの完成後に接続する
* 各フェーズでlint、typecheck、buildを実行する
* 各フェーズに完了条件を設定する

## Codexの作業ルール

各フェーズで以下を守る。

1. 作業前に関連ファイルを確認する
2. 実装方針を提示する
3. 変更予定ファイルを提示する
4. 必要最小限の変更を行う
5. 既存機能を無断で削除しない
6. companyId・officeId・userId・customerIdを確認する
7. API側でも認証・権限を検証する
8. Firestore Rulesを確認する
9. ローディング・空データ・エラー状態を実装する
10. 監査ログ対象を確認する
11. lintを実行する
12. typecheckを実行する
13. buildを実行する
14. 変更内容と未完了項目を報告する
